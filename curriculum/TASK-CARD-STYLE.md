# Как писать шаг урока, чтобы ребёнок понял с первого раза

Правила для текстов в `lesson.json` (панель BlockQuest в VS Code). Собраны по гайдам Codecademy, Code.org, Swift Playgrounds, Scratch-карточек, Raspberry Pi Foundation, Khan Academy и исследованиям Nielsen Norman Group про детей и подростков (ноябрь 2026). Формат файла — в [LESSON-FORMAT.md](LESSON-FORMAT.md).

## Карточка шага: что где

```
3  Фонари: функция glow                       в коде · ≈12 мин
   Три фонаря считают яркость одной формулой. Напиши её один раз.   ← task: одна цель
   1  Открой student/forest.js.                                       ← actions
   2  Над фонарями напиши функцию glow(size), которая возвращает size * 20 + 10.
   3  Замени три вычисления на glow(2), glow(4), glow(6).
   4  Сохрани файл.
   [student/forest.js · над lanternSmall · Открыть]                  ← where
   В ИГРЕ  Те же 50 / 90 / 130. Ничего не изменилось — так и надо.   ← expect
   [Объяснение] [Подсказка 1 из 3] [Код]                             ← по кнопкам
   [Проверить]                                                       ← check
```

## Правила

1. **Одна цель — одно предложение** в `task`, про результат, а не про синтаксис: «Пусть Древень злится, когда здоровья 60 или меньше», а не «Напиши конструкцию if/else».
2. **Одно действие — одна строка** в `actions`. Глагол первым: открой, напиши, замени, сохрани, иди, ударь. 2–4 строки на шаг; если нужно больше — это два шага.
3. **Короткие предложения**: до 12 слов. Второе предложение в строке — только если без него непонятно.
4. **Обращение на «ты»**, без «пожалуйста», без «давайте».
5. **Код в обратных кавычках только для имён и коротких кусочков**: `glow(2)`, `student/forest.js`, `return "calm";`. Цепочку из нескольких строк не вписывать в предложение — она в `code` за кнопкой «Код».
6. **`expect` — что ученик увидит в игре или в карточке, конкретно**: числа, слова, цвет. «Над фонарями 50, 90, 130», а не «фонари заработают».
7. **`explain` — одно «зачем» и одна картинка-метафора**, 2–3 предложения. Новый термин — один раз, с примером из игры.
8. **Подсказки по порядку от намёка к решению**: первая — вопрос («что в трёх строках одинаковое?»), вторая — форма («четыре строки: `function glow(size) {` …»), третья — почти готовый ответ. В подсказках не появляется ничего нового, чего не было в объяснении.
9. **Проверка вместо галочки**, где игра или файл могут подтвердить: `run`, `file`, `game`. Галочка `self` — только для устного шага и там, где игра пока не пишет прогресс.
10. **Без слов «просто», «легко», «очевидно», «это/то»**. Называть вещи по имени: не «эта функция», а `treantPhase`.
11. **Заголовок шага — до пяти слов**, с именем того, что делаем: «Помощник isDanger», «Два случая: if и else».
12. **Никаких заданий на бумаге.** Прогноз говорится вслух перед действием в игре; итог урока — один устный шаг «Расскажи».
13. **Не ставить на карточку диапазон времени из расписания**: панель показывает «≈12 мин» из `minutes`, расписание по минутам — только в методичке.

## Чего не делать (встречается у конкурентов)

- Задание в комментариях кода: цель теряется, как только ученик правит файл.
- Абзац на 3–4 предложения перед действием: дети его пропускают.
- Шаг без цели («используй функцию из шага 1»): непонятно, зачем.
- Подсказка, которую копируют целиком вместо решения, или подсказка с новым синтаксисом.
- Большой скачок между шагами: новый концепт только в скрытой подсказке.
- Картинка вместо текста инструкции: не найти, не выделить, не прочитать вслух.
